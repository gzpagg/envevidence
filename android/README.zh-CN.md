# EnvBench 安卓实验台助手 · 0.6.0 预览版

[English](README.md) · [电脑版文献工具](../README.zh-CN.md) · [截图与验证](../docs/ANDROID.md) · [样品 CSV 格式](../docs/BENCH_CSV.md)

EnvBench（原 EnvEvidence 安卓实验助手）专为水与污水高级氧化、DOM 转化等反应实验设计：倒计时到每个取样点，未选择淬灭剂不能保存样品，实际取样时间与计划时间分别记录，水体基质随反应保存，填写 C/C₀ 后拟合 k_obs。0.4 的计时、计次、照片现象和时间线均保留。主导航为 **实验、计时、记录、我的**。

手机端只做一件事：做实验。文献提取与核验请使用 [EnvEvidence 电脑版](../README.zh-CN.md)。早期版本的学习、任务和便利贴不再显示，但数据保持不变，并包含在每份完整备份中。

## 安装

**0.6.0 尚未发布签名版本。** 每个拉取请求（PR）的 Android 工作流会构建测试 APK（构件 `envbench-android-0.6.0` 中的 `app-debug.apk`）。它使用调试密钥签名，不能覆盖安装已签名的 0.3/0.4：请先导出完整备份，卸载后安装测试 APK，再导入备份。最新正式版本仍是 [0.4.0 签名预览版](https://github.com/gzpagg/envevidence/releases/tag/v0.4.0-android-preview.1)。需要 Android 8.0+，并保持 Android System WebView 更新。0.6.0 沿用相同的应用 ID，使用维护者密钥签名后可覆盖安装 0.3/0.4 并迁移数据。卸载会删除本地数据，卸载前请导出完整备份。

无需账号、Python 或服务器。进入 **我的 → 载入实验演示**，可添加一次虚构的 UV/PDS 反应（含样品和水质数据），不覆盖已有记录。手机端功能不调用模型或 API。

## 一次反应实验

1. 开灯或加入氧化剂时点 **新建反应**，保存即开始计时（t = 0）。选择工艺（UV/PDS、UV/H₂O₂、O₃、芬顿等），填写目标物、氧化剂剂量、波长、辐照强度，以及取样时间表（分钟），例如 `1, 2, 5, 10, 20, 30`。
2. 反应页最醒目的是下一个取样点倒计时：提前 30 秒变为主题色，到点变为琥珀色，超过 30 秒变为红色。迟到仍可取样，系统记录实际时间。
3. 点 **取样** 即锁定取样时刻并打开记录面板。点选所用淬灭剂（Na₂S₂O₃、MeOH、EtOH、过氧化氢酶、抗坏血酸、不淬灭，或自行填写），点选时刻记为淬灭时间；未选择淬灭剂时无法保存。pH、温度、体积用大号 − / + 调节，默认沿用上一个样品的数值。样品按取样顺序编号 S-001、S-002……
4. **水体基质** 记录水体类型、批次、0.45 µm 过滤、是否加标、DOC、UV₂₅₄、碱度、Cl⁻、NO₃⁻-N、Br⁻、电导率与 pH；SUVA₂₅₄ 自动计算并标注为计算值。未测项目留空，并计入 8 项完整度。
5. LC 测定后点 **粘贴 LC 峰面积**，粘贴导出结果：每行 `S-003  12345`（制表符、逗号或空格分隔），或按样品顺序只粘贴峰面积。选择参比（默认 S-001，或手动输入 C₀ 峰面积）并查看预览；无法识别的行会列出，不会猜测。也可直接填写 C/C₀。准一级拟合（以实际取样时间对 ln(C/C₀) 最小二乘）即时给出 k_obs、95% 置信区间、t½ 和 R²；5 个点以上时检验曲率，提示**滞后期**或**拖尾**；取消某行的“拟合”即可排除该点。设置了辐照强度时显示按辐照剂量的 k′E（cm² mJ⁻¹）；填写了氧化剂剂量时显示 k_obs ÷ [氧化剂]₀，用于比较剂量。修改会在样品历史中保留原值；取样与淬灭时间不可修改。表格中的相机按钮可为该样品拍照记录。
6. **样品 CSV** 按[共享格式](../docs/BENCH_CSV.md)导出，每个样品一行，每行附带反应与水质信息。

也可在“计时”页对取样点取样。未设置工艺的普通实验仍与 0.4 相同。

## 其他实验、计时与现象

1. **开始实验**：只需名称，样品标签和实验说明可选。
2. **添加计时**：秒表与倒计时可以并行，自定义名称和识别颜色，支持整组开始/暂停。数量没有人为固定上限，实际规模受设备内存与存储约束。分段、结束和归零均保留历史；倒计时到点后显示已超时多久。
3. **安排取样**：填写实验开始后的分钟数，例如 5、10、20、30。点击“取样”打开上文的记录面板，实际时间与计划时间分别保存。暂停取样提醒不会顺延原始时间点，恢复时仍按实验开始时刻计算。
4. **计次**：大按钮 +1、撤销、新一轮计数；归零不删除历史操作。
5. **记录现象**：实验页直接拍照或写短句，自动关联实验、样品和已进行时长。文字修改保留前一版本；后来加入的照片有独立的加入时间，不将其冒充为原始拍摄时间。
6. **整理实验**：在时间线回看操作和现象；导出 CSV、单个实验 ZIP，或包含原始照片的完整备份。

## 计时提醒

进入 **我的 → 启用计时提醒**，允许系统通知及闹钟权限。权限未完整开启时会在界面提示。应用只安排最近一个到期的系统闹钟，到期后再安排下一个；同时到期的多个计时合并为通知。点击通知直接进入计时页，无需常驻后台服务。

同一次手机启动期间，使用安卓单调时钟计算已进行时长，应用重建或进程重新打开后可恢复。手机重启或数据迁移到另一台设备后，按保存的系统时间恢复，因此跨重启修改手机时间可能影响结果。导入备份中的运行中计时会暂停，避免旧提醒意外重新启动。

强行停止应用、关闭通知声音及厂商省电策略可能阻止提醒。已使用 Android 15 模拟器检查后台通知；实体机相机、长时间运行/重启场景及不同厂商省电策略仍需测试。本版本是预览版，不是校准计时仪器，也未上架 Google Play。

## 照片、备份与旧数据

- 调用系统相机或文件选择器，支持每张不超过 30 MB 的 JPEG、PNG 和 WebP。原始照片及其元数据保留；缩略图仅用于显示。
- 数据与照片保存在应用私有目录，关闭系统云备份和设备迁移备份；实验功能不上传照片或记录。
- 完整 ZIP 包含工作台 JSON、原始照片及预览图。单个实验 ZIP 仅包含该实验及其关联数据，不夹带其他学习记录或文献项目。
- 单次 ZIP 导出/恢复支持最多 512 MB 解压内容；较大的手记可按实验分批导出。导入只添加新的 ID，已有数据不覆盖；同一照片 ID 的内容冲突会明确报错。
- 从 0.3.0/0.4.0 升级时保留原有学习、任务、便利贴和证据记录（不再显示，但保存在完整备份中）。文献提取与核验转到电脑版，历史文献项目仍包含在完整备份中；仍可导入电脑版项目/工作台 JSON。
- 本次不加入 OCR、照片智能解读、语音识别、账号或云同步。

## 构建与验证

需要 JDK 17+、Android SDK 36 和 build-tools 35.0.0；已包含带校验值的 Gradle 8.13 wrapper。

```sh
cd android
./gradlew lintDebug testDebugUnitTest assembleDebug assembleRelease
cd ..
node --test android/tests/*.test.cjs
```

Windows 使用 `gradlew.bat`。[安卓自动检查](../.github/workflows/android.yml) 包含编译、逻辑测试和 Android 15 模拟器测试。发布包在本机用稳定私有签名签署；请私下备份签名密钥，后续升级需要同一身份。签名材料不进入 Git 或 APK。

界面由应用内置 HTML/CSS/JavaScript 显示，Java 负责原子保存、系统时钟、闹钟、通知、相机、文件选择及照片 ZIP。应用不加载远程网页；浏览器预览只验证界面，相机和后台提醒需在安卓中使用。

[验证记录](../docs/ANDROID.md) 区分已完成检查与未验证场景。界面采用暖白、陶土色、细线图标与简洁排版，保留 EnvEvidence 品牌。交互参考 [Time Timer](https://support.timetimer.com/hc/en-us/articles/29258432418203-Time-Timer-App-Free-vs-Paid-Premium-Features)、[LabArchives](https://help.labarchives.com/hc/en-us/articles/11729082137364-Adding-and-Editing-Entries) 和 [Claude Android](https://claude.com/blog/android-app)，无官方合作关系。
